The Request

What You Asked For

"Add a Trash/Recycle Bin feature to the trips dashboard. Part 1 — run an ALTER TABLE to add a deleted_at column for soft deletes. Part 2 — update the trips page: change delete to soft-delete, add a trash bin icon button with a badge count, build a slide-in trash panel with restore support, auto-purge trips older than 7 days on page load, and show a toast on restore."

This was a complete feature addition — no existing code was removed, only extended. The core idea is soft-delete: instead of permanently erasing a trip row, we stamp it with a timestamp and filter it out of normal views, giving the user a 7-day recovery window.

Feature Breakdown

Everything That Was Built

1 · Soft Delete (changed behavior)

The "Delete" button on trip cards no longer issues a DELETE SQL statement. Instead it does: 

UPDATE trips SET deleted_at = now()
WHERE id = [tripId] AND user_id = [userId]

The card fades out and disappears from the grid just like before — the user experience is identical — but the row still exists in the database and can be recovered. The confirmation dialog text was updated from "Delete this trip?" to "Move to trash?" and the confirm button now reads "Move to Trash" to make the reversibility obvious.

2 · Active Trips Filter

The Supabase query that loads your trips now includes .is('deleted_at', null) so soft-deleted trips never appear in the grid: 

SELECT * FROM trips
WHERE user_id = [userId]
  AND deleted_at IS NULL
ORDER BY created_at DESC

3 · Auto-Cleanup on Page Load

Every time the trips page loads, before fetching anything, it silently runs a cleanup that permanently hard-deletes any trip in the trash that's older than 7 days: 

DELETE FROM trips
WHERE user_id = [userId]
  AND deleted_at IS NOT NULL
  AND deleted_at < now() - interval '7 days'

The cutoff is computed in JS (new Date(Date.now() - 7 * 24 * 60 * 60 * 1000).toISOString()) and passed to Supabase's .lt() filter. This happens silently — no loading state, no UI change.

4 · Trash Icon Button + Badge

A dark gray icon button sits next to the "+ Plan a New Trip" button in the page header. It holds a trash SVG icon and, when there are items in the trash, shows a red badge with the count. Badge is hidden when count is 0. Count is fetched during the initial page load and updated locally on delete/restore without a full reload.

5 · Trash Panel (slide-in drawer)

Clicking the trash icon opens a panel that slides in from the right with a blurred backdrop overlay. It's a fixed-position drawer, 420px wide, with its own scroll area.

Header
Title + close
"Trash" heading, X button, subtitle about 7-day expiry
Items
Trip list
Destination, date range, two status pills, Restore button
States
Edge cases
Loading skeleton + empty state when trash is clear

Each trashed trip shows:

  • Destination name
  • Date range — same format as the main grid
  • "Deleted X days ago" pill — shows "today", "1 day ago", or "X days ago"
  • "Expires in X days" pill — color-coded urgency: 5–7 days: gray ≤ 3 days: amber ≤ 1 day: red
  • Restore button (green) — no "View Trip" link; trashed trips are not accessible

Trash items are fetched lazily — only when the panel is opened. They reload fresh each time the panel opens so counts and expiry times stay accurate.

6 · Restore

Clicking Restore on a trash item runs: 

UPDATE trips SET deleted_at = NULL
WHERE id = [tripId] AND user_id = [userId]
  • Item is immediately removed from the trash list (no reload)
  • Trip reappears at the top of the main active grid
  • Badge count decrements by 1
  • A green toast notification slides up: "Trip restored!"

7 · Toast Notification

A fixed-position pill at the bottom center of the screen. It fades + slides up on show, fades out after 2.8 seconds. Uses a spring-easing animation (cubic-bezier(0.34, 1.56, 0.64, 1)) for the slide. Styled green to match the restore action.

Decisions Made

Key Design Choices

Why soft-delete instead of a separate archive table?

A single nullable column on the existing trips table is the simplest approach that doesn't require joins or schema migrations beyond one ALTER. It also means all existing queries only need a single filter clause added — nothing else in the codebase needed touching.

Why fetch trash lazily (on panel open) instead of on page load?

Trash is an infrequently accessed feature. Loading it eagerly on every page view would add a query that most users will never see. Opening the panel triggers the fetch, and it refreshes each time — so counts and expiry times are always fresh.

Why update badge count locally instead of re-querying?

After a soft-delete or restore, incrementing/decrementing a local counter is instantaneous and doesn't require a round-trip. The count is only ever off by one if the Supabase write fails (which is handled — the UI only updates if (!err)).

Why run auto-cleanup on page load instead of a Supabase cron job?

The request specified client-side cleanup. It runs silently before the trips query, so the user never sees expired trash items. A Supabase edge function or pg_cron job would be more robust at scale, but for this app the page-load approach is reliable enough — every session that touches the trips page will clean up its own stale data.

Summary

Net Result

  • Deleting a trip is now reversible for 7 days
  • Active trips grid is unaffected — deleted trips are filtered at the query level
  • Trash panel is accessible from the page header via a badged icon button
  • Expired trash is automatically purged on every page visit
  • TypeScript is fully typed — no any casts added
  • Zero new dependencies — built entirely with existing Supabase client + inline styles
  • The one manual step is the SQL migration (no CLI available in this environment)
